# Reduce noise and improve the usability of your logs with the log reducer

Grepr's log reducer identifies repeated messages in high-volume log streams and aggregates those messages into summarized events. These summarized events reduce the volume of redundant, low-value log events while retaining full context for less common and often higher-value events.

The log reducer is a core step in a Grepr log reduction pipeline, where it runs after log events have been processed by the parsing, filtering, and transformation steps and before they are sent to your configured sinks. By sending summarized events rather than the full set of logs to your observability vendor, Grepr significantly reduces the volume of shipped logs and your observability costs.

Messages that do not match any pattern pass through unmodified. You can also configure _exceptions_ for specific messages or patterns that must bypass the reducer and be forwarded unmodified to your observability platform. See [Bypass aggregation of important messages with exceptions](/transforms/reducer/exceptions).

Log reduction pipelines also persist your unaggregated raw logs in a Grepr data lake, ensuring you maintain full access to your log data while dramatically reducing storage and processing costs. The data lake allows you to query and analyze your raw logs, for example, when an incident occurs or alerts are raised that require access to the full set of logs for troubleshooting or debugging. See [The Grepr data lake](/grepr-platform/data-lake).

When you create a log reduction pipeline, a reducer is added with default settings suitable for many log processing flows. When needed, you can change the configuration settings to meet your requirements. You can modify reducer settings in the UI or through the Grepr REST API. To configure the reducer in the UI, see [Configure the log reducer in a Grepr pipeline](/transforms/reducer/configuration). For API documentation, see the [LogReducer API specification](/apis/api-spec#schema/LogReducer).

## What the log reducer does

The log reducer groups similar messages into patterns. For each pattern, it:

- Forwards a configurable number of raw sample messages unchanged.
- Periodically emits a concise summary of the additional messages that matched the pattern. The summarized events include metadata that provides important context about the aggregated messages and preserves important fields. See [Summary message metadata](#summary-metadata).
- Tags every output event to indicate whether it is a sample, summary, passthrough, or exception. See [Message types](#message-types).

A message passes through unmodified when:

- The reducer doesn't find a pattern for it.
- The selected inputs contain neither message text nor attributes to group by. See [Choose which fields form a pattern](/transforms/reducer/configuration#structured-configuration).
- The message matches a configured exception rule that prevents it from being reduced.

To change how the reducer groups and summarizes messages, see [Configure the log reducer in a Grepr pipeline](/transforms/reducer/configuration).

## Summary message metadata [#summary-metadata]

When the reducer generates a summary message for a pattern, it adds the following metadata fields to the output event that provide important context about the aggregated messages. This metadata allows you to understand the pattern's characteristics and the messages it represents, and to link back to the original raw messages if needed.

| Field | Description |
|:------|:------------|
| `grepr.patternId` | Unique identifier for the pattern. Use this to find related messages. |
| `grepr.rawLogsUrl` | A direct link to view all raw messages for this pattern in the Grepr data lake. |
| `grepr.repeatCount` | The number of input messages included in the summary. This can be useful for metrics and [rewriting queries](/transforms/reducer/exceptions#rewrite-queries). |
| `grepr.receivedTimestamp` | Milliseconds since the Unix epoch when the summary was emitted by Grepr. |
| `grepr.firstTimestamp` | Milliseconds since the Unix epoch of the first message in this summary. |
| `grepr.lastTimestamp` | Milliseconds since the Unix epoch of the last message in this summary. |

## Message types [#message-types]

After processing, each record is assigned a message type, and the `grepr.messagetype` tag is added to output events with one of the following values:

| Value | Description |
|:------|:------------|
| `sample` | The message is a sample of the original log messages that matched a specific pattern. Sample messages are sent through unmodified until the minimum number of samples is reached. |
| `summary` | The message summarizes multiple source log messages that matched a specific pattern. Summary messages are generated periodically for patterns that have exceeded the minimum number of samples. |
| `passthrough` | The message did not match any existing patterns and was sent through unmodified. |
| `exception` | The message matched an exception rule and was sent through unmodified. |
