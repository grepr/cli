# Release notes for October 2026

Grepr released these feature updates, improvements, and bug fixes in October 2026.

## October 16, 2026

{/* ENGT-5792 */}
### Review and correct what your AI agents remember

You can now see the memories every AI agent in your organization recorded on the new **Memories** page in the Agents area, filter them by entity tag, agent, significance, verdict, or text, and open one to read it with links to the investigations it came from. With permission to edit integrations, you can edit a memory, mark it wrong with a note, or delete it, and agents treat the root cause of a memory you marked wrong as ruled out. Each agent's **Memories** step also sets how much the agent searches its memory and which conclusions it records, and can start each investigation with the memories related to its triggering signals. See [_](/ai-agents/memory#review).

### Other improvements and fixes

- {/* ENGT-6088 */} Attribute remapping rules and the Grok parser's **Extract from** field can now name an attribute whose name contains a dot, such as `user.agent` in `{"http": {"user.agent": "curl/8.4.0"}}`, when you write the path as a JSON array of attribute names, such as `["http", "user.agent"]`. See [_](/transforms/remapper#array-paths).
- {/* ENGT-6160 */} The AI assistant opens from the app bar, its model picker lists only text chat models and supports search, and you can copy a reply.
- {/* ENGT-6036 */} Grepr now stores a `NaN`, infinite, or out-of-range number in an incoming log or span as null.
- {/* ENGT-6150 */} Fixed an issue where a dataset or integration could not be deleted after you deleted a pipeline that used it, when an earlier update of that pipeline had failed.
- {/* ENGT-6140 */} Fixed an issue where a search too long for the query engine, such as one containing a large pasted block of text, failed with an internal error that repeated the whole query. Log Explorer, Trace Explorer, **Analyze**, agent investigations, and the Grepr CLI now report that the query is too large so you can simplify it.
- {/* ENGT-6166 */} Fixed an issue where a Datadog Agent payload that was within the size limit when compressed but too large after decompression, such as a large trace payload, failed with a 500 error instead of a 413 error.

## October 14, 2026

{/* ENGT-4985 */}
### Ask an assistant about your logs and pipelines

You can now hold an ongoing conversation with a Grepr AI assistant from a dockable panel in the product. The assistant searches your logs, inspects your pipelines, and can apply changes for you, and it asks before any change takes effect, so you can allow it once, allow it for the rest of the conversation, or refuse it. Conversations are saved, so you can return to one later or carry an investigation an agent already ran into a chat. The assistant is part of AI agents, which are turned on for each organization individually. See [_](/ai-agents).

{/* ENGT-6091 */}
### Manage integrations and datasets with Terraform

You can now create and manage your Datadog, Splunk, New Relic, Sumo Logic, OTLP, and data warehouse integrations, and the datasets inside them, with the Grepr Terraform provider, alongside the pipelines that use them. Reference an integration or dataset from a `grepr_pipeline` resource and Terraform creates them in order. The new resources need provider version 1.2.0. See [_](/admin/terraform-provider#tf-integrations-datasets).

### Other improvements and fixes

- {/* ENGT-6021 */} Span searches in the Trace Explorer return several times faster. Benchmarks show certain queries return 5x faster.
- {/* ENGT-6024 */} You can now collect file statistics on every indexed column of a dataset's raw log table or raw span table, from **Advanced** in the dataset's settings, to make searches faster. See [_](/grepr-platform/indexed-columns#file-statistics).
- {/* ENGT-5999 */} A SQL transform using `VARIANT_VALUE` now reports an invalid type, behavior, or default when you save the pipeline instead of when the job reads its first log, and a misspelled behavior such as `'DEFALT'` is rejected rather than ignored.
- {/* ENGT-6074 */} An investigation link now opens the transcript over the agent's **Investigations** tab instead of on a separate page, so the list keeps its page, filters, and selection while you read a transcript and when you close it. Links you already posted keep working.
- {/* ENGT-6066 */} The Terraform provider now reports that a pipeline's tags cannot be changed after creation, and lists the pipeline's current tags, instead of failing with an invalid plan.
- {/* ENGT-5926 */} Fixed an issue where a literal open range in a Datadog-like query, such as `@code:[* TO *]`, matched every event instead of testing that the attribute exists, as it does in Datadog.
- {/* ENGT-6084 */} Fixed an issue where a Datadog-like query that listed many quoted values for one field, such as the link from a reduced log summary to the logs behind it, failed with an `INTERNAL_ERROR_QUERY_ENGINE` error.
- {/* ENGT-6074 */} Fixed several issues where an open investigation transcript showed fewer turns than the agent had written, including a missing final turn when a run finished between two refreshes, a stale transcript when you reopened a finished investigation, and stalled scrolling partway down a long transcript.
- {/* ENGT-6074 */} Fixed an issue where a link to a deleted agent or investigation showed a session error, or sat on a loading spinner, instead of saying that it no longer exists.
- {/* ENGT-5999 */} Fixed an issue where a `VARIANT_VALUE` default for a `DATE`, `TIMESTAMP`, or `TIMESTAMP_LTZ` path failed the job on the first log missing that path, and where a numeric default such as `'DEFAULT', 0` failed the pipeline when it was saved.
- {/* ENGT-5822 */} Fixed an issue where a pipeline whose filter combined a large number of conditions with `AND` failed to start, and where two comparisons against `CURRENT_TIMESTAMP` in one query could read different times.
- {/* ENGT-5958 */} Fixed an issue where an NRQL subquery matched different events than the same condition written at the top level, and where a subquery with no condition of its own matched nothing.

## October 6, 2026

### Other improvements and fixes

- {/* ENGT-6051 */} Tag keys on logs sent through a Datadog integration are now converted to lowercase, matching the Datadog convention.
- {/* ENGT-6025 */} When you add a field to a never-index list, Grepr now removes its column from the dataset's table on a schedule, 6 hours later by default, which frees the column's place under the discovery cap. See [_](/grepr-platform/indexed-columns#excluded).
- {/* ENGT-5963 */} Composite aggregation keys on a reducer attribute, such as `bytes_sum`, now appear on samples, exceptions, and passthrough messages as well as on summaries, so aggregations over those keys count every message.
- {/* ENGT-6016 */} Fixed an issue where the Trace Explorer ignored the sort order you chose, which made searches over long time ranges slow.
- {/* ENGT-5994, ENGT-6012 */} Fixed an issue where the Trace Explorer returned an error for a dataset that had never received trace data.
- {/* ENGT-6011 */} Fixed an issue where log and span backfills failed with a "Could not submit job" error on some older datasets.
- {/* ENGT-6013 */} Fixed an issue where a dataset's table settings returned an error for a table the dataset had not written yet.
- {/* ENGT-5963 */} Fixed an issue where reducer summaries could contain duplicated or truncated values for an attribute with several composite aggregations that collect lists.
- {/* ENGT-6054 */} Fixed an issue where a pipeline with a SQL transform whose output goes to the **Sinks** step failed to start.

## October 2, 2026

{/* ENGT-5568 */}
### Faster searches on the log attributes and tags you filter on most

Grepr can now index log attributes and tags as their own columns in a dataset's data lake table, so a search that filters on an indexed field reads only that column and skips the files that cannot match. In each dataset's settings, you choose whether Grepr discovers new fields to index, which fields it always indexes, and which it never indexes. Searches return the same results whether or not a field is indexed. See [_](/grepr-platform/indexed-columns).

{/* ENGT-3505 */}
### Detect log patterns from the shape of their attributes

Log reduction can now build patterns from a log's attributes instead of only its message, so structured logs whose message is empty or always the same still reduce into distinct, meaningful patterns. On the reducer's **Patterns** card, you choose whether patterns come from the message, the attributes, or both, whether attribute values count toward similarity or only the attribute keys do, and which attribute subtrees to include or exclude. These settings replace the single structured tokenization switch, and reduction keeps grouping events by the message alone unless you choose otherwise. See [_](/transforms/reducer/configuration#structured-configuration).

{/* ENGT-5821, ENGT-5545 */}
### Import fewer Datadog exceptions and estimate their impact before you build a pipeline

The Datadog integration has a new **Active dashboard threshold** setting that limits dashboard imports to dashboards viewed within the period you choose, so queries from dashboards nobody looks at no longer produce exceptions.

You can also estimate each imported exception against your indexed Datadog logs, so you can see how much volume it would keep before any Grepr pipeline exists. From the integration's exceptions dialog, start an estimation run over a scope and time window, and each exception shows the share of indexed logs it matches in the **% indexed logs** column. Estimating against indexed logs requires an application key with the `logs_read_data` scope. See [_](/integrations#passthrough-estimation).

### Other improvements and fixes

- {/* ENGT-5939 */} Log pipelines evaluate filter, exception, and routing queries faster, especially Datadog word searches, case-insensitive matches, `LIKE` patterns, and long `IN` lists.
- {/* ENGT-5764 */} Log pipelines now have a single **Parsing** step that runs JSON parsing, attribute remapping, and Grok parsing in order, so you can now remap attributes that a Grok pattern extracts.
- {/* ENGT-4711 */} The **Parsed alert queries** table now shows when each Datadog dashboard query was last viewed and how many views it has, and you can filter the table on both.
- {/* ENGT-5821 */} You can now rename an integration, or change settings that no running pipeline reads, such as the active dashboard threshold, without stopping the pipelines that use it.
- {/* ENGT-5655 */} The **Input-Output Lag** metric for trace pipelines now includes the time spans wait before the pipeline reads them, so it reports the full delay from ingestion to output. After a pipeline restarts with a backlog, the metric shows the backlog's real age instead of reading near zero.
- {/* ENGT-5798 */} The pipeline log viewer now has one tabbed settings dialog in place of its two footer dialogs, and no longer shows a loading spinner in the middle of the results while new logs stream in.
- {/* ENGT-5816 */} Fixed an issue where Analyze expressions failed with a "Table not found" error when an `@` attribute name contained a hyphen or slash, such as `@trace-id` or `@app.kubernetes.io/name`.
- {/* ENGT-4718 */} Fixed an issue where an `IN` or `NOT IN` list with a large number of values in an NRQL or Grepr SQL query matched every event instead of filtering.
- {/* ENGT-5798 */} Fixed several issues in the pipeline log viewer, including column selection, a crash in the popped-out view, the diff tab not working when popped out, and an empty link from the reducer step to the sink step.
- {/* ENGT-5934 */} Fixed an issue where metrics chart axes showed too few or too many decimal places for small or fractional values, such as CPU usage.
